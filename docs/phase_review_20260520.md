## 一、项目现状一句话

**系统很完善，策略没验证。** 工程上从数据采集→选股→买入→卖出→盯盘→推送已经全链路打通，但真正跑的daemon策略和回测验证的策略不是同一套。相当于造了一辆好车但没确认发动机能不能跑。

---

## 二、策略真实性审计 — 最大问题

### 策略A(首阴日内)：回测和实现不一致

| 维度 | 回测(ML版) | daemon(纯规则版) |
|------|-----------|-----------------|
| 选股 | ML模型预测Top20 | 2连板+首阴+跌幅排序 |
| 样本 | 211笔/218天 | **0笔大样本回测** |
| PF | 2.23 | 未知(模拟盘3笔PF=1.29) |

**结论：策略A没有对应的大样本回测。** ML已废弃，纯规则版从未独立验证过。

### 策略B(回踩低吸)：和唯一经过验证的S2有4处关键差异

| 维度 | S2回测(验证过) | daemon策略B |
|------|---------------|------------|
| 买入 | 次日开盘价 | 回踩到涨停开盘价(更低) |
| 持有 | 1天 | **2天** |
| 止损 | 不止损(-7%宽) | **-3%紧止损** |
| trailing | 无 | 1.5-3% |

S2回测：5031笔/944天/均+0.50%/PF=1.26/95%CI=[+0.35%,+0.67%]

**致命问题：daemon策略B改了S2的止损逻辑(紧止损vs不止损)，而铁律5明确说"止损是有害的"——5031笔3年回测证明：止损-3%均+0.09% vs 不止损均+0.50%，止损吃掉了80%的利润。**

daemon的-3%止损可能在把赚钱的策略变成亏钱的。

### 策略C：已停用(正确)
PF=0.97无效，3年2077笔。停用是对的。

## 三、我们走过的路 — 时间线

### 做对的事

1. **建立完整的数据基础设施**：baostock 495万条/4年+日K线，涨停池/资金流/龙虎榜等16张表
2. **策略B从追涨改为低吸**：520笔追涨PF=0.40(必亏)→改为低吸，方向正确
3. **停用策略C**：数据验证无效就停，不感情用事
4. **废掉ML**：预测力≈0不纠结
5. **退潮保护**：涨跌比<35%不开仓，13946笔回测验证
6. **944天/10策略扫描**：找到S2(最优策略)，95%CI下界>0
7. **卖出系统从拍脑袋到数据驱动**：v1-v5迭代，最终524笔诚实回测

### 走弯路的事

1. **花太多时间在卖出系统上**：v1→v5搞了5个版本，最终结论是"改善0.22%/笔"。如果把同样的时间花在"让策略B的回测和实现一致"上，价值大10倍
2. **选股优化太多，执行优化不够**：搞评分卡/四维评分/因子验证，但daemon的执行(15秒扫描→回踩检测→买入)一直没有优化到和S2回测一致
3. **ML策略A的回测数字误导了**：PF=2.23是ML选股的，不是当前纯规则版的。可能导致对策略A的过度信心
4. **策略B从S2改版时没有重新回测**：把持1天改成持2天、不止损改成-3%止损，这些改动可能把正期望改成了负期望，但没有验证

## 四、离挣钱有多远？ — 三种情景

### 乐观情景(概率30%)：daemon策略B本质和S2类似
- 买入价更低(回踩)=更好的入场点
- 持2天可能捕捉更多涨幅
- -3%止损虽然有损但在多数日子不触发
- **预期月收益：+2-5%**
- 条件：需要先做daemon策略B的独立回测确认PF>1

### 中性情景(概率40%)：daemon策略B打平或微利
- -3%止损吃掉一部分利润
- 回踩不到位导致交易次数减少
- trailing被打脸几次
- **预期月收益：-1% ~ +1%**
- 基本不亏不赚

### 悲观情景(概率30%)：daemon策略B亏钱
- -3%止损频繁触发(铁律5：5031笔证明止损有害)
- 持2天在退潮市放大亏损
- 回踩买不到好票(只买到继续跌的)
- **预期月收益：-3% ~ -5%**
- 持续运行会亏损

### 关键不确定性
**我们不知道当前在哪种情景里。** 因为daemon策略B没有独立回测。

## 五、回测系统应该怎么设计

### 当前缺陷

1. **回测脚本和daemon代码是两套**：回测用Python脚本算，daemon用不同的逻辑执行。改了daemon不更新回测。
2. **没有"端到端回测"**：只验证了选股或止损的单个环节，没有验证"从选股到买入到持有到卖出"的完整链路
3. **不考虑资金限制**：回测假设全买，实际只能买N只
4. **不考虑执行偏差**：回测用精确价格，daemon有滑点和买不到的情况

### 正确设计：Daemon-in-Loop回测

```
核心思路：用daemon的策略代码做回测，不用独立的回测脚本

[历史日K线] → [daemon选股模块] → [模拟买入(含滑点)]
     → [daemon持有模块] → [模拟卖出(含滑点)] → [统计结果]

每天模拟：
  1. 调用daemon的选股函数(传入历史数据)
  2. 按资金限制选N只
  3. 模拟买入(开盘价+随机滑点0.3-0.8%)
  4. 模拟持有(用日K线模拟盘中走势)
  5. 调用daemon的卖出判断函数
  6. 记录结果

关键：每改daemon代码，自动重新回测，保证回测=实盘
```

### 回测指标设计(必须包含)

| 指标类别 | 具体指标 | 为什么需要 |
|---------|---------|-----------|
| **收益** | 总收益、年化收益、月均收益 | 基础 |
| **风险** | 最大回撤、最大连亏天数、夏普比率 | 能不能扛得住 |
| **稳定性** | 年度/季度/月度胜率、收益标准差 | 策略是否持续 |
| **统计** | Bootstrap 95%CI、PF、盈亏比 | 是否显著 |
| **执行** | 实际成交率、平均滑点、买不到的比例 | 回测和实盘的差距 |
| **成本** | 0.5%基础+0-1%敏感性 | 策略能否活过成本 |
| **衰减** | 最近半年 vs 早期表现 | Alpha是否在消失 |

## 六、未知因素和风险

### 已知未知

1. **daemon策略B的实际PF**：可能是+0.50%也可能是-0.50%，没有数据
2. **策略A纯规则版的实际表现**：0笔大样本回测
3. **回踩到位率**：多少比例的候选票真的会跌到涨停开盘价？
4. **持仓2天 vs 1天**：哪个更好？没有对比数据
5. **-3%止损触发频率**：在5031笔S2数据里，有多少笔盘中跌过-3%但收盘回来了？

### 未知未知

1. **极端行情**：924式全民涨停、千股跌停时策略怎么表现？S2回测已包含但daemon版没验证
2. **市场结构变化**：A股量化资金越来越多，低吸策略可能越来越难做
3. **流动性**：涨停次日低开可能是因为利空，不是正常回调
4. **板块轮动**：选股只看涨停不看板块，可能选到末位票
5. **监管风险**：频繁日内交易可能被重点关注

## 八、一句话总结
