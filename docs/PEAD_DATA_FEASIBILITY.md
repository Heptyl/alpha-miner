# A股PEAD(财报公告后漂移) 数据可行性评估报告

## 评估日期: 2026-06-11

## 一、核心问题：能否获取精确公告发布时间？

### 结论：✅ 可以，通过东方财富API的eiTime字段获取精确到秒的公告发布时间

## 二、数据源详细评估

### 1. 东方财富API (推荐 ★★★★★)

**接口**: `https://np-anotice-stock.eastmoney.com/api/security/ann`

**关键发现**:
- `eiTime` 字段包含精确到秒的公告发布时间，格式如 `2024-10-30 19:19:38:000`
- **覆盖率: 100%** — 2024年10月6419条财务公告全部有eiTime
- 可按股票代码、日期范围、公告类型(f_node)过滤
- f_node="1" 为财务报告分类
- 无需API Key，无认证要求
- 支持分页(page_size最大100)

**时间分布统计 (2024年10月财务公告)**:
```
15:xx =  111 (5.8%)  — 盘后(15:00收盘前发布的极少)
16:00 =  339 (17.8%)
17:00 =  234 (12.3%)
18:00 =  528 (27.7%) — 最多
19:00 =  471 (24.7%)
20:00 =  195 (10.2%)
21:00 =   16 (0.8%)
22:00 =    2 (0.1%)
```
**94%以上公告在盘后(16:00-23:00)发布**，符合A股公告惯例。

**限制**:
- 单次最多返回100条，需分页
- 大量请求可能需要适当延时
- 需要从返回的columns字段识别具体公告类型(年度报告/季度报告等)

### 2. akshare库 (部分支持 ★★★)

**`stock_notice_report(symbol="财务报告", date="20241030")`**:
- 底层调用东方财富API
- **但eiTime字段被丢弃！** akshare源码中将其重命名为"-"后不输出
- 只返回日期精度的"公告日期"字段
- **结论: akshare现成接口不满足需求，需要直接调用API或修改akshare**

**`stock_report_disclosure(market="沪深京", period="2024年报")`**:
- 数据源: 巨潮资讯网
- 返回"实际披露"日期（只有日期精度，YYYY-MM-DD）
- 覆盖率100%
- 包含预约日期和变更记录
- **适用于回溯验证，但时间精度不足**

**`stock_zh_a_disclosure_report_cninfo()`**:
- 数据源: 巨潮资讯网
- 有"公告时间"字段，但巨潮API返回的announcementTime是毫秒时间戳
- **巨潮的时间戳精度只到日期**（当天0:00:00的时间戳），不满足需求

### 3. baostock (不满足 ★★)

- `query_profit_data()` 等接口有 `pubDate` 字段
- 但只有日期精度 (YYYY-MM-DD)，无具体时间
- 数据可能滞后

### 4. tushare (需付费，可能满足)

- tushare pro的 `income()` 接口有 `ann_date` 和 `f_ann_date` 字段
- `f_ann_date` 是实际公告日期
- 但需要有效token (需注册+积分)
- 公告时间精度: 需要验证是否只有日期

### 5. 学术论文数据源

A股PEAD研究常用数据源：
- **CSMAR (国泰安)**: 学术标准，有精确公告日期和时间
- **Wind (万得)**: 有精确公告时间，商业终端
- **CNRDS**: 学术数据库，公告数据精确
- **RESSET (锐思)**: 学术数据库

**注意**: 学术论文中大量PEAD研究使用的是"公告日期"(只有日期)，而非精确时间。原因是：
1. A股绝大多数公告在盘后发布 (>94%)
2. 即使只有日期精度，由于公告几乎都在收盘后，下一交易日作为入场日是安全假设
3. 只有在研究日内效应时才需要精确时间

## 三、PEAD研究数据可行性判断

### ✅ 可行 — 但有注意事项

**满足的数据维度**:

| 数据需求 | 数据源 | 可获取性 |
|---------|--------|---------|
| 精确公告发布时间 | 东方财富API eiTime | ✅ 精确到秒，100%覆盖 |
| 公告日期(备选) | 巨潮资讯/akshare | ✅ 日期精度，100%覆盖 |
| 财务报表数据 | baostock/akshare | ✅ 季度利润表/资产负债表 |
| 日度行情数据 | baostock/akshare | ✅ OHLCV |
| 交易日历 | akshare | ✅ trade_calendar |
| ST/退市标识 | akshare | ✅ 需要处理 |
| 流动性过滤 | baostock/akshare | ✅ 成交额等 |

**入场时间确定规则**:
```
if 公告时间 >= 15:00 (盘后发布):
    首个可交易日 = 公告日期的下一个交易日
elif 公告时间 < 15:00 (罕见，盘中发布):
    首个可交易日 = 公告日期当天(但实操保守取T+1)
```

**实操简化方案** (如果不要求精确到分钟):
- A股94%以上财报在盘后发布
- 用巨潮的"实际披露"日期(日期精度) + 统一取下一交易日即可
- 这也是大部分学术论文的做法
- **简化方案的数据获取复杂度大幅降低**

### 数据获取工作量评估

**精确方案** (使用eiTime):
- 需要直接调用东方财富API
- 全市场年度数据: ~5万条财报公告，需分页500+次
- 预计下载时间: 10-30分钟
- 需要写自定义获取脚本

**简化方案** (只用公告日期):
- 使用akshare `stock_report_disclosure()` 即可
- 每期~5000条，几秒钟
- 加上`stock_notice_report()`按日期获取
- 预计下载时间: 1-5分钟

### 建议

1. **推荐使用简化方案**作为主要数据源，用巨潮"实际披露"日期
2. **用精确方案(eiTime)**做辅助验证和异常处理
3. 入场日统一取公告日期的下一交易日（A股特殊情况下这几乎总是正确的）
4. 如果发现公告日期是交易日且确有盘中发布的，需要eiTime来区分

## 四、风险和限制

1. **东方财富API无官方SLA**: 接口可能随时变更，需要维护
2. **baostock服务器不稳定**: 测试中出现"Broken pipe"错误
3. **历史数据回溯**: 东方财富API的历史数据是否覆盖到2015年以前需验证
4. **财务数据point-in-time**: 需要确认akshare/baostock返回的是初始公告版本还是修订版本
5. **数据量**: 全市场5年数据需要处理约20万条公告记录

## 五、最终结论

**PEAD方向: ✅ 接受 — 数据可行**

关键论据：
1. 东方财富API提供精确到秒的公告发布时间(eiTime)，覆盖率100%
2. 即使不使用精确时间，A股公告几乎全在盘后发布，日期精度足够确定入场日
3. 财务数据可通过baostock/akshare获取
4. 数据获取技术路径清晰，无不可解决的障碍
