# Alpha Miner Web 重设计方案

## 一、现状诊断

### 代码层面
| 问题 | 严重度 | 影响 |
|------|--------|------|
| 17个页面,仅8个有自动刷新 | 高 | 8个页面数据是死的,不更新 |
| 7处硬编码绝对路径 | 高 | 换台电脑就不能跑 |
| 30处重复的sys.path样板 | 中 | 代码冗余,维护困难 |
| services层4个文件各管各的 | 中 | 数据来源不统一,同一数据不同页面不同值 |
| state.py持仓数据硬编码 | 高 | 改持仓要改代码 |
| 总代码10986行,无组件复用 | 中 | 每个页面从头写,风格不统一 |
| CSS写在app.py的markdown里 | 低 | 难维护,不完整 |

### 用户体验层面
| 问题 | 严重度 | 影响 |
|------|--------|------|
| 页面多但核心交易页不突出 | 高 | 用户找不到关键信息 |
| 无统一的数据更新机制 | 高 | 看到的数据可能是5分钟前的也可能是1小时前的 |
| 页面间风格不一致 | 中 | 有的用metric有的用HTML卡片,排版乱 |
| 无Dashboard首页 | 高 | 进来是系统地图,不是交易面板 |
| 无全局交易状态指示 | 高 | 不知道系统在不在跑,持仓盈亏一眼看不到 |

### 架构核心问题
**没有分层。** 每个页面直接访问DB/文件/API, 无统一数据层。
- 同一个"持仓数据", state.py读JSON, 16页读DB, 3页读硬编码
- 同一个"ML候选", 11页读JSON, 15页调函数, 16页调另一个函数
- 结果: 数据不一致,改一处漏三处

### 2.2 三层架构

```
┌─────────────────────────────────┐
│         Presentation            │  ← Streamlit页面(8个)
│         (展示层)                │     只负责渲染,不做数据处理
├─────────────────────────────────┤
│         Data Service            │  ← 统一数据服务(1个)
│         (数据层)                │     所有数据从这里取,保证一致性
│                                 │
│ DataService.get_portfolio()     │     自动缓存+自动刷新
│ DataService.get_realtime()      │     DB/API/文件统一封装
│ DataService.get_ml_candidates() │     盘中实时,盘后用缓存
│ DataService.get_strategy_b()    │
│ DataService.get_account()       │
│ DataService.get_news()          │
│ DataService.get_system_status() │
├─────────────────────────────────┤
│         Data Sources            │  ← 数据源(不变)
│         (数据源层)              │     DB / 腾讯API / 文件
└─────────────────────────────────┘
```

### 2.3 数据实时更新策略

```
场景           刷新间隔   机制
────────────────────────────────
盘中(9:30-15:00)
  行情/持仓     15秒     st_autorefresh + cache_data(ttl=15)
  ML候选        5分钟    cache_data(ttl=300)
  策略B候选     5分钟    cache_data(ttl=300)
  交易流水      10秒     cache_data(ttl=10)
  新闻          30分钟   cache_data(ttl=1800)

盘后(15:00-次日9:00)
  所有数据       不刷新   cache_data(ttl=None)
  手动刷新       按钮     st.rerun()
```

## 四、关键约束

1. **数据一致性**: 所有页面通过DataService取数据,不许直接访问DB/API
2. **自动刷新**: 盘中所有页面自动刷新,零手动操作
3. **响应速度**: 首屏<2秒, 首屏只加载轻量数据(行情),重数据懒加载
4. **配置外置**: 持仓/策略参数从UI编辑,存JSON,不硬编码
5. **路径相对**: 零硬编码路径,基于项目根目录计算
