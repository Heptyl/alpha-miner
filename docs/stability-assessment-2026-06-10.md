# Alpha Miner 稳定性与盈利可行性评估

日期：2026-06-10

## 结论

当前系统适合继续做研究、回测、shadow 和模拟盘验证，不适合接入真实资金。
工程主链路已经能够稳定启动、停止、记录运行账本并 fail closed，但尚未证明任何
当前运行策略具有可持续正期望。

## 可复现证据

- 模拟账户：现金 86,393.87 元，累计盈亏 -5,902.60 元，20 笔平仓，
  胜率 45%，当前无持仓。
- 从持仓表按信号归类：A 4 笔，+380.36 元；B 25 笔，-2,057.76 元；
  C 6 笔，-2,643.48 元。旧记录缺少版本和 run_id，不能用于严格版本比较。
- 策略 B v2 全样本回测：合并模式 661 笔，PF 0.90，胜率 46.9%，
  笔均 -0.326%。该版本没有正期望证据。
- 策略 C 官方回测：19-21 笔，PF 1.10-1.25，总收益 0.56%-1.79%。
  样本太小，且收益依赖少数大赢家，不能据此升级实盘。
- 2026-06-10 数据压测：32 项通过、5 项失败、5 项警告。主要问题是部分
  日线不完整、pre_close/amount 缺失、ML 预测停留在 2026-05-15，以及数据源
  日期不一致。

## 本轮修复

- 恢复被错误归档但仍由 CLI、测试和交易代码引用的 evolution、recommend、
  push、adaptive_weights 和 ML 公共模块入口。
- daemon 本体遵守维护暂停标记，直接执行 start 也不能绕过维护锁。
- shadow 策略在生成模拟订单预告前进行运行模式硬门控，避免污染待执行队列。
- 显式传入 `llm_client=None` 时禁用 LLM，保证新闻分类、市场剧本和测试可复现。
- 将独立数据压测脚本排除出 pytest 自动收集，并使因子注册测试核对当前 YAML
  配置，而不是旧的硬编码数量。

## 主要缺陷

1. 策略收益证据不足。B 已有负期望证据；A 只有 4 笔；C 只有少量回测和
   6 笔旧模拟记录。
2. 历史交易缺少策略版本、配置哈希和 run_id，版本前后表现无法严格拆分。
3. 回测脚本和 daemon 参数不完全同源，部分报告使用 30 天持有，而运行配置是
   5 天，不能直接比较。
4. 日线存在部分交易日不完整，2026-06-09 的 amount 大量为零；分钟线只到
   2026-05-15。
5. ML 预测文件已过期 26 天，相关展示和旧链路不能视为有效输入。
6. Web 能启动，但尚无浏览器级端到端测试、鉴权、权限隔离和真实下单演练。
7. 配置、README、状态报告和实际策略版本存在多处口径冲突。

## 推进计划与时间

- 1-2 周：完成数据完整性门禁、版本化绩效报表、回测与 daemon 参数同源、
  shadow 后验自动回填、每日运行验收。
- 4-8 周：每个候选策略至少积累 30-50 个独立交易日信号，淘汰 PF<=1 或
  置信区间覆盖明显负收益的策略。
- 3-6 个月：在不改参数的前提下完成 100-200 笔模拟交易，覆盖上涨、震荡和
  下跌市场；要求扣除成本后 PF>=1.2、最大回撤可控、月度结果稳定。
- 6-12 个月：只有满足准入门槛后，才考虑极小资金、人工确认、单策略灰度实盘。

以上是工程和统计验证周期，不是盈利承诺。若策略持续无正期望，时间延长也不会
自然产生盈利，应直接淘汰并重新研究。

## 实盘准入门槛

- 所有生产交易记录具备 strategy_version、run_id、config_hash。
- 至少 100 笔独立样本，且不能把同日重复扫描当作独立信号。
- 扣除手续费、印花税、滑点和涨跌停不可成交约束后 PF>=1.2。
- Walk-forward 各阶段多数盈利，样本外结果不依赖单一月份或少数大赢家。
- 模拟盘最大回撤、单日亏损、连续亏损均在预设范围内。
- 数据缺失、行情异常、LLM 异常、进程重启时全部 fail closed。
- 真实下单前保留人工确认、撤单、熔断和日终对账。
